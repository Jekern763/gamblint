# Game Analysis README

This section focuses on the computational analysis of the game itself. Rather than comparing different algorithms, the goal here is to understand the game by looking at all possible states and histories. In particular, this research investigates how the information gained from each peek affects uncertainty, the distribution of the next roll, and the expected value of possible guesses.

The analysis builds the state graph, enumerates the possible histories, calculates metrics for each history, and then aggregates those metrics to look for patterns. The results are saved so that graphs and further analysis can be generated without repeatedly running the full computation.

## code

### `state_graph.py`

Builds the graph of possible game states and the transitions between them. It tracks which next states can occur and the corresponding roll sums, including how many different face combinations lead to the same transition.

### `state_analysis.py`

Takes the state graph and enumerates the possible observable histories. It tracks which states are consistent with each history, how many paths lead to each state, and the probability of each history.

### `analysis_by_history.py`

Calculates metrics for every possible history, including the number of consistent states, state probabilities, uncertainty, next-roll probabilities, and the expected value of possible guesses. This is the main computational part of the analysis.

### `analysis_by_dice_config.py`

Aggregates the per-history metrics by dice configuration and depth. It calculates summary statistics, including means, medians, weighted statistics, and information gain, to show how the game changes as more information is revealed.

### `metric_saver.py`

Runs the main exhaustive analysis and saves the resulting datasets. Run this when the underlying data needs to be regenerated; it is not necessary to rerun it just to make new graphs.

### `graph_generators/config.py`

Loads the saved datasets and provides them to the graph-generation scripts.

### `graph_generators/figure_generator.py`

Generates the main metric plots. These show how different game properties vary with depth, number of possible states, entropy, and dice configuration.

### `graph_generators/correlation_matrices.py`

Investigates relationships between the numerical metrics using Pearson correlation, Spearman correlation, and normalized mutual information. It generates correlation matrices and ranked comparisons to help identify which metrics are related.

### `graph_generators/graph_utils.py`

Contains reusable plotting functions used to generate consistently formatted figures.

## data

Contains the saved results of the exhaustive game analysis.

### `analysis_by_history.pkl`

Stores the results for individual histories, including their consistent states, probabilities, uncertainty measures, next-roll distributions, and expected-value metrics. This is the main dataset for analyzing individual histories and is also used by the small experiment in `vector_analysis/quick_script.py`.

### `analysis_by_dice_config.pkl`

Stores the aggregated metrics grouped by dice configuration and depth. This is used for the summary plots and for examining how the game's properties change as more peeks are revealed.

Both datasets are generated by `code/metric_saver.py`. Since the computation can be expensive, the existing datasets should be reused whenever the analysis itself has not changed.

## figures

Contains the graphs generated from the saved datasets. There are currently 42 plots: 36 metric plots and six correlation/dependence plots.

The metric plots are generated by `code/graph_generators/figure_generator.py`, while the correlation plots are generated by `code/graph_generators/correlation_matrices.py`.

To regenerate the figures, run both scripts from the `research/` directory. To rebuild the underlying data first, run `code/metric_saver.py`, followed by both graph-generation scripts.

## Dependencies

The code depends on `shared/code/analysis_config.py` for the game-state and transition definitions used by the analysis. Keep this file importable under its original module name, `analysis_config`, because the saved history dataset contains serialized state objects.
